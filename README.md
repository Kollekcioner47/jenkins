## О курсе

Курс практический. Мы поднимаем собственный стенд из трёх машин: Jenkins,
Git-сервер и два сервера, на которые выкатывается сайт. Дальше последовательно
проходим всё, из чего состоит работа с Jenkins: задания, агенты, командная
строка, репозиторий, триггеры, параметры, Groovy, конвейеры. В конце —
то, без чего эксплуатация не обходится: секреты и выкат без простоя, Docker,
общие библиотеки, конфигурация как код и восстановление после аварии.

Материал рассчитан на людей, которые знакомы с Linux и командной строкой,
но хотят понять Jenkins не на уровне «набери эти команды», а на уровне
«почему это работает именно так и что сломается, если сделать иначе».

**Что отличает этот курс от большинства вводных материалов:**

- **Объясняется не только «как», но и «почему».** Почему сборки нельзя
  запускать на контроллере, почему пароль, переданный параметром, виден
  в журнале, почему симлинк на релиз надёжнее копирования файлов поверх,
  почему шаг сборки падает с кодом 137.
- **Разбираются поломки.** В каждой практике есть раздел про типичные сбои:
  агент в состоянии offline, «credentials not found», вебхук не доходит,
  конвейер висит в очереди, задание «не видит» переменную. Умение прочитать
  журнал сборки ценится выше знания всех галочек в портале.
- **У каждой практики есть продолжение.** После базовой части идёт
  продвинутая: Docker-агенты, канареечный выкат, откат одной командой,
  общие библиотеки, JCasC, восстановление Jenkins с нуля.
- **Исправлены ошибки прежней версии курса.** Материал несколько лет
  использовался на занятиях, и всё, что в нём не работало, отмечено в тексте
  пометкой `ИСПРАВЛЕНО` с объяснением причины. Это не косметика: адрес ключа
  репозитория Jenkins изменился, плагин для копирования файлов по SSH
  перестал поддерживаться, а в скриптах на Groovy были опечатки, из-за
  которых они просто не запускались.
- **Готовые файлы.** Всё, что разбирается в тексте, лежит в каталоге
  `files/` — скрипты, Jenkinsfile, XML заданий, конфигурация JCasC,
  каталоги `vars/` и `src/` общей библиотеки. Можно применять сразу,
  не набирая вручную.
- **Материал проверяется автоматически.** В репозитории есть два скрипта:
  один проверяет содержимое файлов (XML, YAML, Groovy, shell), второй —
  структуру курса и оформление.

## Что понадобится для занятий

Для прохождения курса нужен собственный стенд. Практика 1 описывает,
как его собрать.

| | |
|---|---|
| **Машины** | 3 виртуальные машины |
| **admin** | 10.0.2.5 — контроллер Jenkins, Git-сервер Gitea, локальный реестр образов |
| **node1** | 10.0.2.13 — агент Jenkins и веб-сервер nginx |
| **node2** | 10.0.2.14 — агент Jenkins, веб-сервер nginx и Docker |
| **ОС** | Ubuntu 26.04 LTS |
| **Ресурсы** | 2 виртуальных ядра, 4 ГБ памяти, диск от 20 ГБ на каждую машину |
| **Сеть** | одна подсеть, доступ в интернет на всех машинах |
| **Учётная запись** | `engineer` с паролем `Console47`, права sudo на всех машинах |
| **Портал** | http://10.0.2.5:8080 — основной интерфейс курса |

### Про портал, белый IP и сертификат

Курс построен вокруг **веб-портала Jenkins**: почти всё делается в браузере,
а командная строка и API разбираются там, где без них не обойтись —
в практике 5 (Jenkins CLI) и в конвейерах.

У стенда **нет белого IP и нет сертификата для HTTPS**. Из этого следуют
три вещи, и все они отражены в материале:

1. **Внешние вебхуки не придут.** GitHub или GitLab из интернета не смогут
   обратиться к Jenkins внутри лаборатории. Поэтому в курсе используется
   свой Git-сервер Gitea на той же машине: вебхук от него доходит до Jenkins
   за миллисекунды, и триггеры разбираются по-настоящему, а не в теории.
2. **Соединение открытое.** Пароли, токены и содержимое сессий идут по сети
   без шифрования. В практиках есть отдельный разбор, как закрыть это
   в рабочей среде (обратный прокси с сертификатом, HTTPS, отдельный порт),
   но на учебном стенде это сознательно не делается.
3. **Адрес — это IP.** Занятия идут с адресами вида `http://10.0.2.5:8080/`,
   без доменных имён.

Если у вас другая подсеть, замените адреса на свои. Ошибка в адресах
проявится позже и будет выглядеть как «Jenkins не видит агента».

### Как устроена каждая практика

Материал разбит на две части:

**Часть 1 — базовая.** Пошаговое выполнение с объяснением каждого шага:
что делает действие, что вы увидите в результате, почему сделано именно так.
Там, где это уместно, отмечены исправленные ошибки прежней версии курса
и объяснено, почему прежний вариант не работал.

**Часть 2 — продолжение.** Более сложные темы, которые отличают учебный
пример от рабочей эксплуатации: производительность, безопасность,
разбор поломок, автоматизация рутины.

В каталоге `archive/` лежат материалы прежней версии, которые полностью
заменены новыми: `1_install_jenkins.txt`, `2_administration_jenkins.txt`,
`6_deploy_from_github.txt` и страница сайта из каталога `files for practics`
(теперь `archive/files-for-practics/index.html`). Что и чем заменено,
описано в `archive/README.txt`: там же приведены ключевые фрагменты
прежних текстов, на которые ссылаются пометки `ИСПРАВЛЕНО` в практиках.

Лицензии: [`LICENSE`](LICENSE) — MIT для кода,
[`LICENSE-CONTENT`](LICENSE-CONTENT) — CC BY-NC-SA 4.0 для текстов практик.

Все файлы в `files/` снабжены комментариями: что делает каждый параметр
и на что обратить внимание. Часть комментариев объясняет не «что», а «почему
именно так» — например, почему рабочая копия задания не должна лежать
на контроллере.

## Как начать

> **Быстрый старт:** соберите стенд по практике 1, проверьте доступность Jenkins,
> затем проходите практики последовательно. Снимок виртуальных машин лучше сделать
> до начала экспериментов.

1. **Соберите стенд** по практике 1. Это единственный шаг, который делается
   один раз и требует отдельной подготовки машин.
2. **Проверьте, что Jenkins жив:**

   ```bash
   systemctl status jenkins
   curl -s -o /dev/null -w '%{http_code}\n' http://10.0.2.5:8080/login
   ```

   Ответ `200` означает, что портал отвечает.
3. **Проходите практики по порядку.** Каждая следующая опирается
   на предыдущие: выкат в практике 11 идёт на агентов, которых мы
   подключали в практике 4, и забирает код из репозитория, созданного
   в практике 6.
4. **Сделайте снимок виртуальных машин**, пока стенд чистый. Дальше будет
   много экспериментов — вплоть до удаления пользователей и восстановления
   Jenkins из копии, — и возможность откатиться за пару минут экономит
   время.

Практики 1–9 можно проходить и на одной машине, если собрать три не
получается: агенты появятся в практике 4, но роли node1 и node2 там
обязательны для дальнейшего. Практику 4 в этом случае стоит пройти
ознакомительно.

## Соглашения в материалах

> **Важно:** версии в курсе зафиксированы намеренно. Экосистема Jenkins меняется
> быстро, поэтому перед практикой полезно сверить фактические версии командой
> проверки, приведённой в соответствующем разделе.

Материалы писались и проверялись на конкретных версиях, и это указано
сознательно: экосистема Jenkins меняется быстро, и команда, работавшая два
года назад, сегодня может не работать вовсе.

| Компонент | Версия |
|---|---|
| Jenkins | LTS 2.528.1 |
| Java | 21 (`openjdk-21-jre`) |
| Ubuntu | 26.04 LTS |
| Gitea | 1.24.x |
| Docker CE | 28.x |
| nginx | из репозитория Ubuntu |
| Плагины Jenkins | список — в [`files/jcasc/plugins.txt`](files/jcasc/plugins.txt) |

Практики, где это важно, содержат команду проверки версии — например,
`java -jar jenkins-cli.jar -s http://10.0.2.5:8080 version` или
`gitea --version`. Это надёжнее любой статьи, включая эту.

**Пароли в курсе.** Учётная запись `engineer` с паролем `Console47`
и пароли, которые встречаются в примерах, — учебные. Они опубликованы
в открытом тексте именно потому, что стенд изолирован. Не переносите
их в рабочую среду: там пароли создают случайными и хранят в секретах,
а не в материалах курса.

## Чего в курсе нет — сознательно

| Не разбирается | Почему |
|---|---|
| HTTPS и сертификаты | На стенде нет сертификата; в практике 1 (раздел 8) объяснено, как это делается в рабочей среде |
| Kubernetes и контейнерная оркестрация | Курс про Jenkins; Docker разбирается ровно настолько, насколько нужен конвейеру |
| Jenkins в облаке и платные плагины | Не нужны для понимания предмета и требуют внешних учётных записей |
| Сборка Java-проектов через Maven и Gradle | Требуют отдельного стека; принципы конвейера от этого не меняются |
| Устаревшие плагины (Publish over SSH и подобные) | Заменены штатными средствами; разобраны в практике 11 как исторический пример |

## Обратная связь

Если нашли ошибку или что-то не работает на вашей версии Jenkins —
присылайте описание: версия Jenkins, что делали, полный текст ошибки
из журнала сборки. С текстом ошибки исправление попадёт в курс гораздо
быстрее.
