Пояснения к файлам Docker (практика 12).

Файл daemon.json выглядит недружелюбно: в нём нет ни одной подписи.
Так и должно быть — формат JSON не поддерживает комментарии, а служба
Docker разбирает этот файл строго: неизвестное поле в нём приводит
к отказу запуска. Поэтому пояснения живут здесь, а в файле только
рабочие ключи.

ЧТО ОЗНАЧАЕТ КАЖДЫЙ КЛЮЧ

  insecure-registries
      Список реестров, к которым Docker обращается по http, без
      сертификата. Наш реестр на 10.0.2.5:5000 работает именно так.
      Без этой строки push завершится ошибкой «http: server gave HTTP
      response to HTTPS client»: Docker по умолчанию требует HTTPS.
      В рабочей среде этого ключа быть не должно — там реестр ставят
      за HTTPS с сертификатом внутреннего центра сертификации.

  log-driver и log-opts
      Журналы контейнеров пишутся в файлы с ограничением 10 МБ и трёх
      файлов на контейнер. Без ограничения долго живущий контейнер
      однажды займёт весь диск — и это будет выглядеть как «Jenkins
      перестал работать» без всякой видимой причины.

  live-restore
      Контейнеры продолжают работать, пока служба Docker перезапускается.
      Для стенда это удобно: обновление Docker не останавливает сайт.

КУДА КЛАСТЬ И КАК ПРИМЕНИТЬ

  sudo install -m 0644 daemon.json /etc/docker/daemon.json
  sudo systemctl restart docker
  docker info | grep -A2 'Insecure Registries'

ПОЧЕМУ ЭТОТ ФАЙЛ НУЖЕН НА КАЖДОЙ МАШИНЕ С DOCKER

Настройка действует на уровне демона Docker, а не реестра. Jenkins
на контроллере и агент на node2 — это два разных демона, и на каждом
нужна своя копия файла. Забыть про вторую машину легко: сборка и push
с контроллера пройдут, а запуск контейнера на node2 упадёт с той же
ошибкой про HTTPS.
